# Dual VHD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the OSD mount a second VHD/IMG as TSConf's SD card #2 (Z-Controller CS2), with the physical secondary SD card used only for a slot that has no image.

**Architecture:** `hps_io` goes to `VDNUM=2`. Two `sd_card` instances share `sd_buff_addr/dout/wr`, each with its own `sd_lba/sd_buff_din/sd_rd/sd_wr/sd_ack/img_mounted` bit. A 2-bit `vsd_sel` says which slots hold an image; it drives per-slot `ss`, the MISO mux, the physical-pin chip select and the LEDs. All changes are in `TSConf.sv` plus one README line.

**Tech Stack:** SystemVerilog (Quartus 17.0 Lite via Docker, `tools/qbuild.sh`), MiSTer `sys/hps_io.sv`, `sys/sd_card.sv`.

**Spec:** `docs/TASK-dual-vhd.md` (facts re-checked against the source on 2026-11-13; see "Findings" below).

## Findings (re-checked, beyond the brief)

- `hps_io` ports with `VDNUM=2`: `img_mounted`, `sd_rd`, `sd_wr`, `sd_ack` are `[1:0]`; `sd_lba[2]`, `sd_buff_din[2]` are unpacked arrays; `img_readonly`, `img_size` stay shared. `img_mounted` is a one-hot pulse (`io_din[VD:0] ? io_din[VD:0] : 1'b1`), so `|img_mounted` means "any mount".
- `sd_card` has a 1-bit `img_mounted`, 1-bit `sd_rd/sd_wr/sd_ack`, and `sd_buff_addr [8:0]`. The current instance uses `.*`, which also binds `clk_sys`, `img_size`, `sd_buff_*`, `sd_lba`, `sd_rd`, `sd_wr`, `sd_ack`, `img_mounted` by name. Both new instances must connect every one of those explicitly.
- `sd_act` today is a bus-toggle monitor on `sdmosi`/`sdmiso` (1,000,000-cycle stretch), not tied to a card. With two slots it must be split by who owns the active chip select.

## Review Focus

- Only image 2 mounted: card 1 must be the physical card (`SD_CS = sdss`), card 2 the VHD. Wrong wiring boots from nothing.
- Both mounted: physical `SD_CS` must stay 1 and `SD_SCK`/`SD_MOSI` must idle, so the real card never sees traffic.
- Eject (`img_size == 0`) of one slot must not disturb the other slot's `vsd_sel` bit or its card state.
- Mounting slot 2 while slot 1 is idle must still pulse `reset_img` (machine reset) and not hang the reset timer.
- LED_DISK must not light for VHD traffic and LED_USER must not light for physical-card traffic.
